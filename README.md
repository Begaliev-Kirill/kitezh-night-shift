# Ночная смена шлюза «Китеж»

Практика по C++ на структуры и классы. На неё заложены **3 часа**.

Нужно провести ночную очередь судов через однокамерный шлюз. Структура хранит запись о судне. Класс хранит камеру: уровень, затворы и тех, кто уже внутри, связаны правилами, и снаружи эти правила нельзя сломать присваиванием. Отдельно есть функция смены: она решает, кого взять в одну перекачку, а кого вычеркнуть раньше, чем насос откажется работать.

Линейка «влезает ли по метрам» нарочно не умеет ничего про скорую и негабарит. Это разные виды правил, и лежат они в разных местах.

## Что здесь относится к теме

- `Vessel`, `Refusal`, `ShiftReport` — структуры. Это данные, которые копируют и передают дальше. У записи о судне нет состояния «затворы открыты».
- `validateVessel` и `fitsInChamber` — свободные функции над структурами.
- `Lock` — класс. Недопустимую камеру нельзя собрать, присвоив поля снаружи.
- `runNightShift` создаёт камеру внутри и наружу отдаёт только отчёт. Живой шлюз из функции не торчит.

Наследования, виртуальных функций и шаблонов в решении не нужно. Хватает C++17: `std::string`, `std::vector`, `std::optional`, методы и `const`.

## Как распределить три часа

1. Прочитать этот файл и тесты камеры. Около 20 минут.
2. Сделать `validateVessel` и `fitsInChamber`, пока группа `vessel` не станет зелёной. Около 30 минут.
3. Реализовать `Lock`. Около 70 минут. Пока камера врёт, смену писать рано: смена водит настоящий объект `Lock`.
4. Реализовать `runNightShift`. Около 50 минут.
5. Оформить pull request. Около 10 минут.

Если время кончилось на камере — сдавайте её. Группы тестов независимы по смыслу: красная смена не отменяет зелёную камеру.

## Сборка и тесты

Нужен компилятор с C++17 (g++ 7+, clang++ 5+) и CMake 3.16+. Из корня репозитория:

```bash
cmake -S . -B build
cmake --build build -j
./build/kitezh_tests
```

То же самое одной командой: `make test`. Удалить сборку: `make clean`.

Без CMake:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -Iinclude -Itests \
  src/vessel.cpp src/lock.cpp src/shift.cpp \
  tests/main.cpp tests/test_vessel.cpp tests/test_lock.cpp tests/test_shift.cpp \
  -o kitezh_tests
./kitezh_tests
```

Зелёный прогон заканчивается строкой `итого: 36/36` и кодом возврата 0. На `main` лежат заглушки: они собираются и честно падают. Это каркас, а не сломанное условие.

Тесты можно и нужно читать. Это часть условия, включая ожидаемый порядок в больших сценариях. Править файлы в `tests/` нельзя. Если сценарий кажется несправедливым — напишите об этом в pull request, проверку не подгоняйте.

Имена тестов сгруппированы: `vessel`, `lock`, `shift`. Имеет смысл чинить первую красную группу, а не прыгать в ночь целиком.

## Какие файлы ваши

Менять можно только:

- `src/vessel.cpp`
- `src/lock.cpp`
- `src/shift.cpp`
- закрытую секцию `include/kitezh/lock.hpp` (поля и приватные методы)

Публичные сигнатуры, `tests/`, `CMakeLists.txt` и этот файл не меняются. Вспомогательные функции держите в `.cpp`, в анонимном пространстве имён: в заголовок им не нужно.

Каталог `build/` и бинарник `kitezh_tests` в git не кладите.

## Легенда

Очередь на ночь — это порядок радиодокладов, а не один физический ряд у причала. Судно «вверх» ждёт у нижнего бьефа и идёт в верхний. Судно «вниз» ждёт у верхнего бьефа и идёт в нижний.

```text
верхний бьеф                          нижний бьеф
~~~~ [верхний затвор]  камера  [нижний затвор] ~~~~
         глубина 42 дм              глубина 28 дм
```

Камера одна. Смена начинается так: уровень нижний, оба затвора закрыты, внутри никого, тактов насоса 0.

| Константа | Значение | Где лежит |
| --- | --- | --- |
| `kChamberLengthM` | 36 м | полезная длина |
| `kGapM` | 1 м | только между соседними судами, не у стен |
| `kLowDepthDm` | 28 дм | глубина на нижнем уровне |
| `kHighDepthDm` | 42 дм | глубина на верхнем уровне |

Длина и осадка намеренно в разных единицах. Сравнивать осадку с длиной бессмысленно: у полей разные имена (`length_m`, `draft_dm`). Числа не копируйте по коду, берите константы из `include/kitezh/geometry.hpp`.

## Суда

`Vessel` — агрегат. Поля публичные, своих конструкторов у него нет.

`validateVessel` возвращает `std::nullopt`, если запись можно рассматривать дальше. Иначе ровно одна строка, первая сработавшая проверка:

1. пустой `call_sign` → `"empty call sign"`
2. пробел, таб или перевод строки в позывном → `"bad call sign"`
3. `length_m <= 0` или `length_m > 36` → `"bad length"`
4. `draft_dm <= 0` → `"bad draft"`

Позывной `Китеж-1` и `A_1` — нормальные. Пробел внутри — нет.

`fitsInChamber(inside, next)` отвечает только на вопрос метров: сумма длин плюс один зазор на каждую пару соседей не больше 36. Одно судно зазора не платит. Примеры, которые закреплены тестами:

- 36 одно — влезает, 37 — нет
- 18 и 17 — влезают (36), 18 и 18 — нет (37)
- 10, 10 и 14 — влезают (36), 10, 10 и 15 — нет
- негабарит в этой функции ни при чём: 20 м негабарита и 10 м соседа по линейке влезают

## Камера

`Lock` бросает `kitezh::LockError` (не голый `std::runtime_error` и не `std::logic_error`). Текст исключения любой непустой: тесты проверяют тип и то, что камера не изменилась. Наблюдатели (`level`, `gate`, `pumpCycles`, `inside`) — `const`.

`inside()` возвращает копию. Элемент 0 вошёл раньше всех и выйдет первым. После `enter` исходный `Vessel` можно менять как угодно: внутри уже другая запись.

Повторно открыть открытый затвор или закрыть закрытый — пустое действие, не ошибка.

Ошибка на `open`, `pump`, `enter` и `exit` не меняет уровень, затворы, состав внутри и счётчик тактов. Сначала проверьте, потом меняйте поля.

### Затворы

- Нижние открываются только на нижнем уровне, верхние — только на верхнем.
- Оба сразу открыты быть не могут.
- Насос работает только когда оба закрыты. Иначе такт не тратится.

### Насос

`pump` переключает уровень на противоположный и прибавляет 1 к счётчику. Если хотя бы у одного судна внутри осадка больше глубины нового уровня, насос отказывается: уровень и счётчик прежние, судно остаётся внутри.

Обратной дороги нет. Судно «вниз» с осадкой 30 дм входит в верхнюю воду (30 ≤ 42) и застревает: опустить камеру нельзя, нижние ворота на верхнем уровне не открыть, выпустить его назад метод `exit` не умеет. Поэтому смена такое судно внутрь не ставит. Камера сама «всю дорогу» не предугадывает: `enter` смотрит только текущую глубину.

Осадка, равная глубине, ещё проходит: 28 дм на нижнем уровне — да, 29 — нет.

### Вход

`enter` кладёт копию, если всё ниже верно. Иначе камера как была, включая тех, кто уже внутри.

- `validateVessel` без ошибки
- такого позывного внутри ещё нет
- осадка не больше текущей глубины
- открыт входной затвор: вверх — нижний, вниз — верхний
- негабарит входит только в пустую камеру; к негабариту не входит никто
- `fitsInChamber` согласен

Затвор `enter` сам не открывает и не закрывает: следующая баржа той же партии заходит в те же ворота.

### Выход

`exit(call_sign)` выпускает только голову очереди и только если открыт её выходной затвор: вверх — верхний, вниз — нижний. Чужой позывной, пустая камера или закрытые выходные ворота — ошибка, состав не меняется. Выход тоже не закрывает затвор.

Ручная проводка одного судна вверх, с которой имеет смысл начать отладку: открыть нижние, войти, закрыть, перекачать, открыть верхние, выйти, закрыть. Получается верхний уровень и 1 такт. Судно вниз с пустой камеры начинается с перекачки наверх, поэтому такта два. Оба сценария есть в тестах `lock`.

## Ночная смена

`runNightShift` возвращает отчёт и на очередях из тестов не бросает исключений. Сомнительное судно попадает в `refused` до `enter`.

Поле `reason`:

| reason | Когда |
| --- | --- |
| `duplicate` | этот позывной уже встречался в очереди |
| `invalid` | `validateVessel` вернул ошибку |
| `draft` | запись годная, но `draft_dm > 28` |

Порядок проверок именно такой. Позывной занят с первого появления, даже если та запись сама `invalid` или `draft`. Второе судно с тем же именем — `duplicate`, в камеру оно не идёт. `draft_dm == 28` проводить можно: нижняя вода ещё держит.

Вычеркнутые суда не стоят в очереди. Они не разрывают партию тех, кто остался.

`passed` — позывные в порядке выхода. `refused` — в порядке исходной очереди. `pump_cycles` — это `Lock::pumpCycles()` после реальной проводки, а не формула «на глаз». Лишняя перекачка «на всякий случай» ломает точный счётчик.

### Как набирается партия

Пока кто-то ждёт:

1. Первое оставшееся судно — основа. Его направление называется D.
2. Негабарит никого с собой не берёт. Партия из него одного, даже если по метрам сосед влезал.
3. Иначе идём дальше по очереди. Флаг «в этой партии уже кого-то пропустили» сначала снят. Судно берём, только если направление D, это не негабарит, метры сходятся с уже набранными и либо флаг снят, либо это скорая. Иначе флаг поднимается, судно остаётся ждать.
4. Флаг умирает вместе с партией. Следующая партия смотрит на хвост заново.
5. Скорая не начинает ночь раньше судна, которое уже стоит первым. Она только вклинивается в открытый набор своего направления.

Проводка партии:

1. Если уровень не входной (вверх — нижний, вниз — верхний), одна перекачка пустой или уже занятой по правилам камеры.
2. Открыть входные ворота, завести суда партии по порядку, закрыть ворота.
3. Перекачать на выходной уровень.
4. Открыть выходные ворота, выпустить в том же порядке, закрыть.

После партии оба затвора закрыты.

### Два разбора

Очередь: А обычное вверх 10 м, Б обычное вниз 10 м, В скорая вверх 10 м.

В первой партии основа — А. Б другого направления, его пропускаем. В — скорая вверх и влезает к А (10 + 1 + 10). Б остаётся ждать. Партии: `[А, В]`, затем `[Б]`. Старт на нижнем уровне, первая партия тратит 1 такт и оставляет верхний. Б входит сверху без пустой перекачки и тратит ещё 1. Итог: прошли `А В Б`, 2 такта.

Очередь: Г обычное вниз, Д скорая вверх, Е скорая вверх. Все по 10 м.

Г уже первое, скорые его не обгоняют. Потом Д и Е одного направления и влезают вместе. Прошли `Г Д Е`, 3 такта.

И обратный случай, чтобы не вывернуть флаг наизнанку. А обычное вверх 20 м, Б скорая вверх 20 м, В обычное вверх 10 м. Б к А не влезает (41 м). В к А по метрам влезло бы (31 м), но Б уже пропущена, а обычное судно не вклинивается. В следующей партии Б стоит первой и забирает В. Прошли `A B C`, 3 такта, не пять: Б и В едут вместе.

Ночь из теста `shift / ночь целиком` собирается этими же правилами. В README её порядок не расписан: он лежит в тесте как контрольная лента.

## Сдача: pull request

Решения не присылайте в исходный репозиторий. Иначе чужая ночь окажется в общем списке pull request.

1. Сделайте fork на свой аккаунт.
2. Ветку ведите от `main` и назовите `solution/<github-login>`. В `main` форка каркас не дописывайте.
3. Доведите тесты локально до `итого: 36/36`.
4. Запушьте ветку и откройте pull request **в свой fork**: база `main`, сравниваемая ветка `solution/<github-login>`.
5. Заголовок: `Китеж — Фамилия Имя`.
6. Текст возьмите из шаблона `.github/pull_request_template.md`. Шаблон подставится сам, если pull request открыт из форка.

В тексте нужно три вещи: что успели, как именно набираете партию (своими словами, не копией этого файла), последняя сводка тестов. Если что-то осталось красным — напишите, какой тест и что уже пробовали.

Во вкладке Actions форка один раз разрешите workflows. Проверка собирает проект и запускает `./build/kitezh_tests` на ветках, кроме `main`, и на pull request. Локальный прогон всё равно обязателен: в отчёт идёт его сводка.

Не добавляйте в pull request посторонние файлы: `build/`, сгенерированный `ya.make`, дампы отладчика, чужие практики.
